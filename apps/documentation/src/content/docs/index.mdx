## Welcome

**chapay — port watcher** is a macOS menu-bar app that lists the TCP ports in `LISTEN`, explains
what each process is, and kills the one you point at. This repository holds the app, its landing
page and this documentation site.

New here as a user? Start with [Install chapay](/desktop/install) and
[Using chapay](/desktop/usage).

### Topology

| Piece         | Path                     | Role                                                                      |
| ------------- | ------------------------ | ------------------------------------------------------------------------- |
| Desktop app   | `apps/desktop`           | **chapay**: Tauri 2, Rust core plus a React renderer. The product         |
| Landing       | `apps/fullstack-fn-only` | TanStack Start app on one Cloudflare Worker; serves the landing page only |
| Documentation | `apps/documentation`     | This site (Astro Starlight)                                               |
| Packages      | `packages/*`             | DDD + Hexagonal template (Todo example); dormant, kept on purpose         |

The desktop app is local-first: it never calls the Worker and has no backend. In the web app, auth
(Better Auth), the todos demo and the database are **disabled** until it needs accounts; the code
stays in the tree (see [ADR 0005](https://github.com/csdev19/port-watcher/blob/main/docs/adr/0005-disable-web-auth-and-database.md)).

## Quick Start

### Prerequisites

- **macOS** with Xcode Command Line Tools
- **Bun** — package manager and runtime
- **Rust** (rustup) — for the desktop app

`bun run setup` checks all of that, installs dependencies and builds the shared packages.

### Installation

```bash
bun run setup

bun run dev                 # landing + docs + the Tauri desktop app
bun run dev:desktop         # just the desktop app
bun run dev:fullstack-fn    # just the landing
```

No `.env` is needed to run the landing: it reads no required variables while auth and the
database are disabled.

## Tech Stack

### Monorepo

- **Package manager**: Bun (workspaces + catalog)
- **Build orchestration**: Turborepo
- **Lint / format**: oxlint + oxfmt

### Desktop app

- **Shell**: Tauri 2 (Rust core: `listeners`, `sysinfo`, `nix`)
- **Renderer**: React 19, Vite, TanStack Query, CSS Modules

### Landing (web)

- **Framework**: React 19 with TanStack Start
- **Routing**: TanStack Router (file-based)
- **Server calls**: TanStack Start server functions (`createServerFn`)
- **Data**: TanStack Query
- **UI**: `@port-watcher/web-ui` (shadcn/ui) + Tailwind v4
- **Forms**: TanStack Form with Zod validation (template, dormant)
- **Auth**: Better Auth (email + password) — disabled
- **Database**: PostgreSQL with Drizzle ORM — disabled
- **Validation**: Zod v4

### Documentation

- **Framework**: Astro Starlight

## Project Structure

```
port-watcher/
├── apps/
│   ├── desktop/               # chapay: Tauri 2 menu-bar app (Rust core + React renderer)
│   ├── fullstack-fn-only/     # TanStack Start landing (auth/DB code present but disabled)
│   └── documentation/         # This site
│
├── packages/
│   ├── domain/                # Zod schemas, types, repository interfaces (leaf)
│   ├── application/           # Use cases (depend on domain interfaces only)
│   ├── infra-db/              # Drizzle schemas, repositories, mappers
│   ├── infra-auth/            # Better Auth base config
│   ├── infra-env/             # Zod env schemas
│   ├── web-ui/                # Shared React components (built dist/)
│   ├── tokens/                # Design tokens -> CSS custom properties
│   ├── i18n/                  # use-intl catalogs (en/es), provider, core
│   └── config/                # Shared tsconfig
│
└── turbo.json
```

**Dependency rule:** `domain <- application <- infra-*`. Only apps wire them together. The desktop
app imports none of these runtime packages; they are the template the web app was cloned from and
are kept deliberately.

## Key Concepts (the dormant template stack)

The sections below describe how the web app's template layers work. They are **not live** in the
shipped landing, which uses none of them; they apply once auth and the database are re-enabled.

### Schema-first

Zod schemas in `packages/domain` are the single source of truth — server function input validation,
client forms, and database mappers all derive from them.

```typescript
export const todoSchema = z.object({
  id: z.uuid(),
  title: z.string().min(1),
  completed: z.boolean(),
  createdAt: z.coerce.date(),
});

export const createTodoSchema = todoSchema.pick({ title: true });

export type Todo = z.infer<typeof todoSchema>;
```

### Server functions over HTTP endpoints

A server function is the adapter: it validates input, checks the session, builds the repository and
runs the use case. The use case never knows it is being called from TanStack Start.

```typescript
export const listTodos = createServerFn({ method: "GET" })
  .inputValidator((input: PaginationQuery) => paginationQuerySchema.parse(input))
  .handler(async (ctx) => {
    const session = await getAuthSession();
    if (!session) return { data: null, error: { message: "Unauthorized" } };

    const db = createDatabaseClient(env.DATABASE_URL);
    const repo = new TodoRepository(db);
    return listTodosUseCase({ repo, userId: session.user.id, pagination: ctx.data });
  });
```

Types flow end to end without a generated client: the function's return type _is_ the contract.

## Security (when auth is re-enabled)

- **HttpOnly cookies** — session tokens are never exposed to JavaScript
- **Server-side validation** — every server function re-checks the session
- **Parameterized queries** — Drizzle ORM
- **XSS protection** — React escaping by default
