# Environment Variables

## How Env Vars Are Loaded

| App/Package                       | Method                                                                    | Source File                                                  | When                       |
| --------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------- |
| **fullstack-fn-only**             | Zod-validated `process.env` (`src/env/server.ts`)                         | `apps/fullstack-fn-only/.env` (dev), wrangler secrets (prod) | Runtime (server functions) |
| **fullstack-fn-only** (client)    | Vite `import.meta.env`                                                    | `apps/fullstack-fn-only/.env`                                | Build-time                 |
| **infra-db** (drizzle migrations) | `dotenvx run -f apps/fullstack-fn-only/.env` from the root `db:*` scripts | `apps/fullstack-fn-only/.env`                                | Migration-time             |

Wrangler auto-loads `.env`, which is why `wrangler.jsonc` must never grow a `vars` block — it would
drift from that single source of truth.

---

## Variables by Context

| Variable             | Server functions | Client | infra-db | Sensitive? |
| -------------------- | ---------------- | ------ | -------- | ---------- |
| `DATABASE_URL`       | Yes              | -      | Yes      | **Yes**    |
| `BETTER_AUTH_SECRET` | Yes              | -      | -        | **Yes**    |
| `BETTER_AUTH_URL`    | Yes              | -      | -        | No         |

The schema that enforces this is `fullstackServerEnvSchema` in
`packages/infra-env/src/fullstack-server.ts`. Adding a variable means adding it there first —
the app fails fast at boot if it is missing.

## Open item: encrypted secrets with dotenvx

`DATABASE_URL` and `BETTER_AUTH_SECRET` live in plaintext in `apps/fullstack-fn-only/.env`, which is
gitignored and therefore shared out of band. [dotenvx](https://dotenvx.com) (AES-256 + secp256k1)
encrypts values inline so the `.env` file itself can be committed:

```bash
# before
DATABASE_URL=postgresql://user:pass@host/db

# after `dotenvx encrypt`
DOTENV_PUBLIC_KEY="03f98bf6e00bce..."
DATABASE_URL="encrypted:BCV9qZmblsUm77..."
```

The private key lives in `.env.keys`, which is never committed.

**Status:** the root `db:*` scripts already invoke `dotenvx run -f apps/fullstack-fn-only/.env`, but
`@dotenvx/dotenvx` is not yet a dependency of this repo and no file is encrypted. Adopting it means:

1. Add `@dotenvx/dotenvx` as a root devDependency.
2. `dotenvx encrypt` the app `.env`.
3. Add `.env.keys` to `.gitignore`.
4. Store `DOTENV_PRIVATE_KEY` in a password manager and as a CI secret.
5. Optionally wire `dotenvx ext precommit` into `lefthook.yml` so an unencrypted secret cannot be
   committed.

Deployment secrets are managed as GitHub Actions secrets today and need no change.
